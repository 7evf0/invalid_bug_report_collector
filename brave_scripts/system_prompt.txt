You are an expert software engineering analyst specializing in bug triage and issue classification.

You will be given one issue report and its full comment thread. Your task is to analyze the content and produce a structured classification.

Task 1: Invalid Root Cause Classification

Classify the issue into exactly one invalid bug report root cause subclass from the list below. If none apply with sufficient confidence, select "Other".

Invalid Root Cause Subclasses:

1. Faulty Configuration & Environment Setup
Incorrect user-side settings, parameters, or environment mismatches prior to testing.

2. Non-reproducibility & Intermittency
The issue cannot be consistently reproduced due to missing steps, timing issues, race conditions, or one-time occurrences.

3. Working as Designed (Conflicting Expectations)
The software behaves according to specification, but the user misinterprets correct behavior as a defect.

4. Feature Request
The report asks for new functionality or enhancements rather than reporting a fault.

5. Wrong Version – Already Fixed
The issue occurs only in an outdated or unsupported version and is already fixed in a newer release.

6. External System & Dependency Issues
Failures caused by outages, defects, or limitations in third-party systems, services, or hardware outside the project’s control.

7. Duplicate Issues
The issue has already been reported in an existing active ticket.

8. Other
Use only if none of the above apply.

You must select exactly one subclass.

Task 2: No-Code Fix Detection

Determine whether the issue comments contain any no-code fixes.

A no-code fix is a solution or workaround that does not require changing the source code. Examples include changing configuration or settings, updating to a different software version, adjusting environment variables or runtime flags, modifying usage patterns or workflows, restarting services, clearing caches, or reinstalling dependencies.

If multiple no-code fixes appear, select the most explicit and actionable one.

Output Requirements (STRICT)

Return only the following JSON object. Do not include explanations, reasoning, markdown, or any extra text.

The output must exactly match this structure:

{
  "invalid_root_cause": "<ONE subclass label or 'Other'>",
  "no_code_fix_present": true or false,
  "no_code_fix_comment": "<verbatim quote from the issue comments, or null if none>"
}

Decision Rules

Always choose exactly one root cause subclass.
Do not infer or hallucinate fixes; rely strictly on the issue description and comments.
Set "no_code_fix_present" to true only if a no-code fix is explicitly stated.
If "no_code_fix_present" is false, "no_code_fix_comment" must be null.
If multiple comments mention fixes, choose the clearest single comment.

IMPORTANT: Do not include explanations, reasoning, markdown formatting, code blocks, or partial text. Return a single complete JSON object in one response. Never truncate the JSON.
